# CodeReview Minimal — 手搓一个代码审查智能体

> 给"**需要审代码、但不需要写代码**"的人准备的代码审查工具。
> 你拿到别人提交的代码，想快速判断质量、安全性、该不该合并——用它。
> 一个自包含的 Python 文件，零第三方依赖，纯标准库就能跑。

[![License](https://img.shields.io/badge/License-Apache--2.0-blue.svg)](LICENSE)

## 它解决什么问题

技术负责人、QA、审计者、验收方常常面临：**代码不是自己写的，但要负责判断它行不行。** 现状是：

- 看不懂/没时间读每一行，凭感觉打勾
- 没有"检查清单"，漏掉 SQL 注入、硬编码密钥这类致命问题
- 想让 AI 帮忙看，又不想为一个工具装一堆依赖、配一套大框架

这个工具把"代码审查"拆成**可复现的静态检查**：丢一个文件或一个目录进去，它用 AST 扫出语法、未用 import、圈复杂度、命名、安全问题，给出 0-100 分。零依赖、纯本地、可审计——这正是"反过度工程"的体现：**能用一个文件解决的，不引入一个框架。**

## 核心能力

### 1. 静态分析（纯标准库，零依赖，不调模型）

| 检查 | 内容 |
|------|------|
| 语法 | `ast.parse` 语法错误 |
| 未用 import | AST 引用分析，找出没用的导入 |
| 圈复杂度 | 函数复杂度 >10 标记 |
| 命名规范 | 函数小写 / 类大写 |
| **安全** | SQL 注入、命令注入(shell=True/os.system)、危险 eval/exec、**硬编码密钥**、不安全反序列化 |

按严重级扣分：critical -20 / major -10 / minor -3，满分 100。

### 2. 可选 LLM 增强审查（OpenAI 兼容，需配置）

静态分析只查"规则"，查不了"过度工程"。配一个 LLM key 后，它会额外审查：
- **过度工程**：未要求的功能/只用一次的抽象层/能用标准库替代的第三方依赖
- **可证伪改进**：每条 critical/major 问题必须给出"修复后预期哪个行为/测试会通过"，禁止空泛建议

不配 key 也能用（纯静态），配了更强。

## 用法

```bash
# 审查一个文件
python review.py 你的代码.py

# 审查整个目录的 .py
python review.py 项目目录/

# 只要得分
python review.py 项目目录/ --score-only

# JSON 输出(可接 CI / 脚本)
python review.py 文件.py --json

# 启用 LLM 增强审查
export LLM_API_KEY=sk-xxx
python review.py 文件.py --llm
```

## 设计原则（方法论）

这个工具背后是一套"手搓 vs 大框架"的立场：

1. **反过度工程** — 能用一个文件解决的审查需求，不引框架。加抽象前先问"值不值"。
2. **规则优先，LLM 兜底** — 能静态判定的走规则（快、准、零成本、可复现），规则覆盖不了的才调模型。
3. **可证伪** — 所有审查结论必须可被行为验证（修复后预期什么会变），不要空泛建议。
4. **零依赖可部署** — 纯标准库，拷到任何机器/CI 就能跑。
5. **为"审的人"设计，不是为"写的人"** — 输出是结论、得分、建议，不是让写代码的人看的过程。

## 安装

无需安装。只要 Python 3.9+：
```bash
# 直接下载 review.py 就能用
python review.py <文件或目录>
```

## 局限（诚实）

- 只支持 Python（`*.py`）。静态分析基于 AST，其他语言没有内置检查。
- 静态规则是启发式的：**能抓典型问题，不能证明代码正确**。安全 check 有已知的误报边界（用 `_strip_self_check_code` 处理了扫描器自指误报）。
- LLM 审查依赖外部模型，非必需。
- 它不是静态分析器（ruff/bandit）的替代品，是"不想装工具链时的一个文件方案"。
